# MinPI with incomplete feature availability

The manuscript is in `thesis-paper/minpi-tree.pdf`. Its LaTeX entry point is `thesis-paper/main.tex`. The standalone manuscript archive places the entry point and its bibliography, table and style alongside `main.pdf`. Build with pdfLaTeX, BibTeX, pdfLaTeX and pdfLaTeX in that directory.

The supervised MinPI study uses seven held-out UCI sources, each with seeds 42–46. The learner is a depth-limited random forest. For each nonempty acquisition size the selector computes the expected excess Brier loss (classification) or squared loss (regression) under a uniform mask of that size. A worst-size guard and intact validation metrics determine the accepted width. The registered portfolio includes an MDI path and a MinPI path. The analytic versus Monte Carlo comparison uses the same 35 source–seed splits and its own locked searches and forecasts. These are two experiments on seven study populations. [Data provenance and split units](../experiments/minpi_rework/validation_predictive.md) · [Supervised protocol](../experiments/minpi_rework/predictive_confirmation.md) · [Monte Carlo protocol](../experiments/minpi_rework/predictive_mc_confirmation.md)

The four-source wide-input study uses a separate archive, five seeds per source and its own timing protocol. The six original prepared tasks are development evidence for the supervised selector. The earlier 13-source, five-seed teacher-fidelity study and the separate five-source recalibration study had both been opened during development of this objective. Their original signed forecasts remain reproducible, and their outcomes retain the scope of their own protocols. ## Offline score and table replay

Unzip `minpi-tree-replication.zip` into a new directory. From its root, use a Python environment with the versions in `thesis-paper/tree-requirements.txt`. This workflow was exercised with Python 3.13 on Windows. Dependencies and typesetting tools are supplied by the runtime. The scorer uses the unmodified bytes in the source archives and the recorded forecasts. All 29 raw public inputs are included (7 primary, 4 wide-input and 18 earlier). To fetch them afresh, use `python -m experiments.minpi_rework.<provider> --fetch`; the five provider modules are `validation_predictive`, `wide_veto_data`, `validation_panel`, `validation_wide` and `validation_exchange`.

```powershell
$root = (Get-Location).Path
$env:PYTHONPATH = (Join-Path $root 'src') + [IO.Path]::PathSeparator + $root
python thesis-paper/tree_release.py verify --tex
```

On a POSIX shell, run `PYTHONPATH="$PWD/src:$PWD" python thesis-paper/tree_release.py verify`. Add `--tex` if TeX Live with the manuscript packages is available. A fresh checkout can use the shared interpreter through `thesis-python.ps1` instead of changing its editable installation.

Verification checks six public forecast archive hashes. For each of the 70 supervised study and simulation-comparison receipts it restores the frozen predictions, sparse path increments, sparse path incidence and JSON selection file. It rebuilds the held-out cardinality-risk and predictive scores, repeats the independent explicit-mask audit on one seed per source, reconstructs the benchmark timing summaries from signed measurement rows, and regenerates the typeset results from the frozen score tables. For the separate 20 wide-input fits it checks the released forecasts, restores interleaved timing observations, and recomputes the five reported score and timing tables. It also replays the earlier 65+25 locked runs, including scores from the two separately archived ranking controls. The support-canonicalization study adds 55 receipts for the same seven and four sources. All 235 public run receipts and 90 historical six-source arm-family receipts are checked. Calibration and timing observations retain their original hardware, masking and split conditions.

The exact feature-lattice and early-veto controls were added after the seven-source outcomes had been opened. The verifier checks 510 small synthetic lattice costs, refits all 35 public splits, and compares every released lattice support, risk and predictive score. Elapsed time varies on a new machine. For the veto benchmark it regenerates the six paired summary tables from both sets of repeated measurements on the 18 development and seven external sources. The original clocks are in `thesis-paper/evidence/minpi_rework/predictive-veto-timing/{repeats,native-repeats}.csv`.

The Beijing follow-up evaluated recorded outages across all twelve stations in a common chronological split. It uses the same public archive as the earlier single-station experiment. The verifier reconstructs the eligible station-days and rescores the locked forecasts, including paired calendar-block intervals. ## Recomputing models

To fit the supervised selector and export a predictor, run `python -m experiments.minpi_rework.predictive_rf_deploy fit --dataset german --seed 42 --model forest.npz` from the extraction. Use `python -m experiments.minpi_rework.predictive_rf_deploy inspect --model forest.npz` to list its retained inputs. To predict new rows, run `python -m experiments.minpi_rework.predictive_rf_deploy predict --model forest.npz --input rows.csv --output predictions.csv`. For an ordinary dataset, supply three disjoint labeled CSVs for fitting, voting and width acceptance. The deployment guide describes the flags and optional row-level availability masks. [Supervised forest deployment](../experiments/minpi_rework/predictive_rf_deploy.md)

Add `--reachable-only` to the fitting command to export the input schema after pruning every descendant of a stopped split. This preserves the selected path's predictions under additional availability masks. The verifier exercises the exported classifier and regressor and compares deployments against frozen seven-source forecasts.

The shared project package, search implementations, formal files and build specifications accompany the measurements.
