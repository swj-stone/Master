# 冻结规则的首次土耳其邮件外部验证

解析还发现原始行号 517（从零起）的 ham 记录正文为空；它有合法标签，保留为零词项记录并接受相同的标签无关重复清理，不删除或补写正文。首次启动在候选评分前因非空正文断言中止，`reliability-mail-20261117a` 仅有启动 manifest，正式两轮另存新目录。

本协议在计算任何候选在此来源上的结果之前保存。数据为 UCI Turkish Spam V01 的原始邮件，来源为 https://archive.ics.uci.edu/dataset/530/turkish+spam+v01 。本地原始压缩包为 `data/raw/turkish-mail-v01.zip`，SHA-256 为 `3d3c7e4254e607059a901b47bf9cac1a06429bb0b7bbfad5e22e80f84c0b6e29`；仅解析其中 UTF-8 BOM 编码的 `trspam.csv` 的 `Text` 和 `Classification` 字段。

原始文件校验发现官网 826（330 spam、496 ham）与下载包不符：包内实际有 825 封带标签邮件（329 spam、496 ham），以及最后的 `,,496` 汇总尾行。尾行没有正文或有效标签，不能作为样本。标准 CSV 存在未转义的正文引号，直接 pandas 读取失败；不使用跳过坏行。实现保留正文换行，以每条记录末尾 `,spam` 或 `,ham` 的换行界标定位原始记录，仅移除 CSV 字段的外层引号及还原双引号转义。独立使用 Python csv.reader 解析、合并正文中被拆分的逗号字段，验证 825 条每条标签和分词集合均相同。原始字节和解析摘要保留，所有实验以实际 825 条有效标签为来源，不虚构缺失的一封邮件。该解析修正于任何候选评价前完成。

唯一主候选为 `reliability_document_top_from_training` 的已冻结默认规则：在旧单次最多 512 行训练子样本产生的两个交叉拟合方向内，各零／一同伴层取较小增益，再取层间最小值。种子、强同伴、99% 正票量预算、平方根下界和半宽上界保持既定规则。此来源未用于选择公式、系数、预算或分词规则；首次外部验证之后不据其结果调参。旧单次 minPI 是独立对照。

沿用现有文本实验的默认 `CountVectorizer` 分词器和二元词项表示。先以不使用标签的完整词项集合检查重复，删除属于重复集合的所有记录，再以 `StratifiedKFold(3, shuffle=True, random_state=39191)` 分折。每折词表仅由训练邮件建立；删除训练内常量列，对每个方法提供全部剩余变化词项。排除投影到训练词表后与任何训练记录完全相同的测试词项集合。记录行号、词表、CSR 索引的摘要以及各项排除数量，防止重复信息泄漏。三折算法种子依次为 1129、2027、3469。

每折固定 10 个臂：reliability、旧单次 minPI、全特征、半宽 F 检验、半宽卡方、半宽单词边际岭增益、半宽随机，以及 reliability 同宽的 F、单词边际岭增益和随机。宽度匹配对照免费获得候选宽度。所有方法使用相同冻结的 StandardScaler 与 RidgeClassifier 下游；每次完整计入选列、模型训练及预测。词表建立为共同输入准备成本，单独记录并另报计入该成本的比值。

仅复用冻结 `refined_document_benchmark` 的方法、模型、计时和汇总函数，由新 runner 显式注入本 provider，不修改冻结源。每个独立进程中先预热，每臂轮换 10 次，运行两个独立计时进程，独占正式计时 CPU。两个进程须保存完全一致的支持、分数和预测；之后分别在新进程复现。新协议、provider、runner、原始包、全部候选和复用源及预编译库均记入 SHA-256 manifest。再以独立审计程序从原始逐次计时重算跨进程交集；每折补充 20 个固定种子同宽随机支持，以判断投票质量。

成功必须同时实际删列、平衡准确率相对全特征下降不超过 0.02、总耗时严格更短。逐个基线比较同时要求相对该基线下降不超过 0.02、总耗时严格更短、列数不更多，且保持全特征标准。另报宽度至多多 10% 及总耗时至少快 10% 的敏感性结果。采用 1e-12 仅处理分数的浮点表示边界，并保留原严格标记和变动数量。全留与任何失败均不得计作成功；三折来自同一来源，不称作三个独立数据集。
