# Pivotal minPI 的预测质量与端到端耗时

后续迭代改变了跨规模最低分的取法，并在 UCI HAR 的官方跨被试划分上检验了相邻规模重新拟合版。[条件重新拟合、跨批失败与跨被试结果](predictive-iteration.md)

本次修改从近邻投票版 pivotal minPI 出发。评估目标是在给定特征预算下保留新样本上的预测质量，并计入筛选、取列、训练和预测的总耗时。原始浮点实现和原始精确实现均用作对照。以下算法使用了不同的选取规则。

## 算法设计

| PivotalSupportSelector 的 rule | 核心计算 |
|---|---|
| grouped | 在最多 256 条训练样本上，按类别解释方差或与连续目标的平方相关排序。按此顺序选代表列，与已选代表的绝对相关达到 0.90 时跳过。然后在代表列上重新找近邻、构票、计算各同伴规模贡献，并取最低分。代表数恰等于预算时可直接返回。 |
| loss | 将最多 256 条训练样本分两半，轮流在一半上为每个特征拟合单变量岭模型，在另一半上计算相对仅含截距模型的平方损失变化。分类使用独热标签。误差降低投正票，增加投负票，持平弃权。对这张新票表精确求跨规模最低贡献。 |
| masked_loss | 在每个训练半折拟合一次包含所有列的岭模型，在另一半上将各列依次替换为拟合折均值，冻结模型系数。遮住该列导致平方误差上升时投正票。保留跨规模最低贡献。线性结构允许从完整预测直接减去单列预测项。 |
| conditional | 每选一列就把它的票固定在后续联盟中，重新计算剩余各列的带符号边际贡献，每轮选取跨规模最低分最高的候选。第一步等价于原精确打分。开销随所选列数增长，基准仅在 10% 预算下比较。 |

代表列的候选数量、相关阈值和损失投票所用的岭模型都是本次研究的具体选择。各变体与原版同用 0、4、16 个同伴的默认设置，遇到不足的同伴数会按各自游戏的可用人数截断。各变体均针对各自定义进行精确计分。static 仍为兼容旧调用的默认规则。

~~~python
from minppi_mofs.support_selector import PivotalSupportSelector

selector = PivotalSupportSelector(rule="grouped", fraction=0.50, random_state=1129)
X_train_small = selector.fit_transform(X_train, y_train)
X_test_small = selector.transform(X_test)
~~~

## 用训练期验证来决定保留多少列

作为预算选择的示例，允许验证平衡准确率或 R² 比全特征低 0.02，在满足条件的候选中取平均端到端耗时最短者，全特征也可入选。这个容忍度是实验假设。候选宽度为 10%、25%、50%、75% 和全宽，F 筛选按同样的容忍度单独选择。Gas 只用批次 1–7 选择，材料只用原训练部分的分组划分选择。名单冻结后重新拟合，重放已知的历史留出集。

两项任务均选中了 75% 的分组版。Gas 的后续三批上平衡准确率为 0.738，对应全特征的 0.667，配对耗时比为 0.76。材料的留出配方组上 R² 为 0.6969，全特征为 0.7184，相差 0.0215，略超训练期的容忍度，配对耗时比为 0.77。六个重放配置的代表列数都恰等于预算，跳过了 pivotal 打分，故不能将这两项收益归给投票。Gas 和材料的 F 策略分别取得 0.8370 和 0.7018。进行一次内层校准的估算成本分别为 11.27 s、4.19 s，远大于单次最终拟合所省的时间。ISOLET 半宽实验有 474–491 个代表竞争 309 个位置，确实执行了 pivotal 选列。

## 两篇参考文献带来的对照

Zhao、Liu 与 Parilina 的论文在第 3–5 页用固定预测模型评估特征联盟，联盟外的特征替换为参考值。第 4 页的 CIS 是 Centre of the Imputation Set。其分配公式对所有列加上相同的常数，按 CIS 排序等价于按单列联盟价值排序。文中实验比较了 ShapG、PFI 和全特征。我们的 CIS 对照选择负平方损失为效用，保留原联合模型的系数，只打开候选列，其余列全部替换为训练均值。PFI 的另一组实验在独立训练子集打乱一列，允许该列取不同样本的实际值。[Strategic inputs](../../example-paper/2510.24982v2.pdf)

Kaur 等人的 Strategic Feature Selection 讨论可被策略性操纵的输入。在第 10–11 页，算法联合选择特征子集与岭正则强度，按其部署后损失进行局部搜索。Gas 与材料实验没有操纵成本矩阵。我们采用相同的下游岭参数网格 0.1、1、10，做固定划分的敏感性分析；这里没有拟合操纵模型，也没有以测试集挑选正则参数。[Strategic Feature Selection](../../example-paper/2606.18867v1.pdf)

训练期比较均保留 10% 的特征。Gas 上，原版近邻投票、联合模型遮蔽投票、同张票表的简单净票数、CIS 的平衡准确率分别为 0.577、0.732、0.767、0.714。材料配方开发折上对应的 R² 为 0.542、0.540、0.564、0.578。这组材料实验使用三折 GroupKFold；前述总耗时表按另一套固定组划分，故两处的材料基线数值不同。结果支持在 Gas 上改动投票定义，也表明在这两个数据源上跨规模最低分均低于同票表的简单净票数。[配对损失与 CIS](../../results/minpi-study/masked-loss-dev-20261117/paired.csv) · [PFI 与正则参数敏感性](../../results/minpi-study/held-permutation-control-20261117a/summary.csv)
## 在同一张票表上改变最低分的计算

按同伴数分层后，各层出现决定票的机会不同。为检验这个因素，将每层的有符号枢轴贡献除以该层各列平均绝对枢轴贡献，跳过完全没有决定票的层，再取最低分。在保留 10% 特征的 Gas、材料和 Digits 开发折上，原最低分、归一化最低分、简单净票数三者的平均得分依次为 0.7325／0.7456／0.7669、0.5404／0.5443／0.5641、0.6619／0.6655／0.6652。Digits 的九次配置中只有一次改变了入选列。层尺度解释了部分平均差距，三个数据集尚未显示稳定的归一化优势。[逐折支持集与分数](../../results/minpi-study/masked-opportunity-20261117/paired.csv)

## 低精度损失下的耗时基线

在岭模型下，置换一列后的预测可以用原预测和该列系数直接更新。用独立的训练期子集评估置换损失，21 个划分与种子组合在两档预算下均与直接置换得到相同的入选列和最终预测。保留 50% 时，Gas 的平衡准确率为 0.8726，全特征为 0.8756，端到端耗时中位数为 38.6 和 71.9 ms。材料的 R² 为 0.7093 和 0.7281，耗时为 20.6 和 33.1 ms。以接近全特征分数并减少耗时为目标时，后续 minPI 版本应与这个实现按相同预算比较。[配对耗时与预测分数](../../results/minpi-study/held-permutation-linear-20261117a/summary.csv) · [置换计算等价性核验](../../results/minpi-study/held-permutation-linear-20261117a/audit.csv)
## ISOLET 半宽预算下的随机、CIS 和置换对照

沿用半宽实验的三个按样本分层划分，每次从 617 列中选择 309 列。随机基线按每个划分的种子作一次均匀无放回抽样。CIS 使用交叉拟合的负平方损失。PFI 的两档设置都在外层训练数据内分层留出样本，对三个共享的随机排列计算类别均衡错误率；小档最多用 256 行拟合、128 行评估，大档用 512 行评估、其余训练行拟合。所有方法最后都在外层训练集重拟合相同的岭分类器。

| 方法 | 平均准确率 | 端到端耗时（ms） |
|---|---:|---:|
| 随机选列 | 89.71% | 455 |
| 单变量 F 检验 | 89.32% | 473 |
| CIS | 90.99% | 473 |
| 小样本 PFI | 90.58% | 530 |
| 大样本 PFI | 91.56% | 1,816 |
| 原版 minPI | 90.99% | 445 |
| 分组筛选，关闭投票 | 90.44% | 433 |
| 分组 minPI | 91.33% | 448 |
| 全特征岭分类器 | 92.12% | 1,342 |

每个设置计时三次，先取划分内中位数再跨划分平均。分组 minPI 在三个划分上都高于随机、单变量 F 和小样本 PFI，对大样本 PFI 为一次高、两次低。[81 次配对调用](../../results/minpi-study/isolet-half-baselines-20261117/isolet.csv) · [设置与源码指纹](../../results/minpi-study/isolet-half-baselines-20261117/protocol.json)
