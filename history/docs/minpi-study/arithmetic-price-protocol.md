# Price of exact membership at three budgets

Use the 42 measured panels from the three-budget study and its archived exact targets. The panel identifiers, budgets, peer counts and ballot hashes are fixed in `results/minpi-study/budget-comparison/targets.csv`. Rounding up to 2%, 10% and 50% of the width compares a narrow screen, the original operating point, and a half-width selection. The five diabetes panels give the same integer budget at 2% and 10%; these appear in both budget summaries. For each panel regenerate all ballots, check their hash, and independently compute the full rational ordering using `direct_layer` and `direct_minimum` before timing. Compare all three archived supports to that order. This study uses training arrays only; the MHEALTH arrays contain precomputed windows.

Compare the released exact selector after tightening bounds on all-zero columns, exact anchor pruning, the verified floating-point proposal, and pure floating-point pruning. Both floating-point policies use the same pruned binary64 selector. Verification starts with anchor intervals on every column, refines the proposal, and refines outsiders only if their anchor upper bound reaches the weakest proposed lower bound. If strict separation fails, apply the exact boundary membership rule. Charge for producing the proposal, checking it and any correction. Inside the safe common-denominator range exact anchor pruning and minPI have identical code: measure that call once and assign its duration to both. Evaluate the pure float support against the integer order but allow genuine swaps in the recorded outcome.

Run one unrecorded warm-up and five recorded calls per policy and budget, as in the original timing study. Use one numerical-library thread, permuting all distinct policy and budget pairs within each round (schedule seed 73139). Begin each call with in-memory training arrays, construct new ballots, and stop when the support is returned. Separate the construction and scoring times and exclude input loading, reference calculations, output checks and predictive fitting. The score component measures the same code available to callers who already hold a ballot matrix. It follows construction within the timed call and is not a separate cold-cache benchmark. Verify each resulting ballot and support outside the clock. No held-out loss is measured.

Use panel medians over repeats before dividing minPI time by comparator time. Within each budget and arithmetic range report the median and interquartile range of the 21 panel ratios (linearly interpolated percentiles), with source-level summaries, extrema and absolute times available in the release. A repeated split or seed contributes a panel, not an independent population. For an application that permits changes in the returned columns, a predictive loss tolerance and comparison on deployment-representative splits must be defined separately.
