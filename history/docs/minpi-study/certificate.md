# Exact top-budget screening

The full scorer returns a ranking and each feature's contribution at every requested peer count. A caller who only needs a support can instead call `select_minpi_support(X_train, y_train, fraction=.1, task="classification", random_state=1129)` from `minppi_mofs.certified_minpi`. It returns original column positions in ascending order. For a disjoint test matrix, use these same positions. A full-budget call returns all positions.

The largest peer count provides an upper bound for each column's minimum across counts. Start with its highest h columns, break ties by original position, and refine these columns using all counts. Let the smallest refined score be the cutoff. An outside column whose upper bound is less than the cutoff cannot outrank the h incumbent scores. Refine all remaining outside columns at or above the cutoff and sort the surviving exact scores. Equality enters the refinement stage to preserve ties at the budget boundary. Every weight uses the original p-column population. Narrowing the population itself would change the target.

The algorithm was developed after observing the frequency of support agreement between the minimum and the largest tier in the main study. Its support identity follows from the upper bound for any matrix. The retrospective study of work saved uses all 55 original training splits without test labels. It reconstructs the training vote matrices and compares the selected original positions both to the full computation in the same engine and to the archived main-run selections. The separate synthetic timing study uses six matrices per width and five measurements per implementation, in randomized order after warm-up. The original all-score function, the new engine with refinement disabled, and the certified engine each receive the same fixed vote matrix and budget. Witness construction and downstream fitting are outside these measurements.

The implementation stores log binomial coefficients only for the peer counts present in the witnesses, at most five count vectors and the normalization count. It accumulates positive and negative contributions in a fixed order. The tests include all 6,561 two-witness, four-column ternary matrices at all four top budgets, duplicate columns and cases where the initial shortlist must be enlarged. Formal statements cover the combinatorial identity and the screening implication. Floating-point calculation of probabilities, construction of witnesses, and measured speed are checked separately.

A second timing from raw training rows measures whether any scoring savings remain visible after witness construction. Use all eight primary benchmark sources and their five frozen training splits, with the same 10% budget. Randomize the order of the three implementations separately per split and repetition. Discard the first repetition as warm-up and take the median of the next three. Compare the full public ranking API, an exhaustive pass with the new engine and the certificate. Rebuild the witnesses for each fit, check every support against the archived selection, and exclude dataset loading and downstream model evaluation. Run this stage with the `training` argument in place of `timings`. These two timing panels were specified before benchmarking the new engine.

A final retrospective control priced the weaker shortcut of returning the largest tier alone. On the same 40 real/benchmark training splits, fix the vote matrix and compare the certificate with computing only the largest tier using the same validation, count-table, reduction and stable tie rules. Verify each output against its corresponding archived arm. Time the two scoring paths in randomized order, discard a warm-up and use the median of five repetitions. The `single` stage writes [these measurements](../../results/minpi-study/certificate/single-tier.csv). It excludes witness construction. The full-minimum guarantee cost median ratios of 1.12 on Gisette and 1.19 on ISOLET relative to the one-tier shortcut, which happened to return the same supports on both datasets.
