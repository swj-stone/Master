# Native-integer control and exact dispatch

During review the common denominator was found to fit a signed machine word on some recorded panels. Before timing the alternatives, fix the following comparison. For every previously studied panel compute D, the least common multiple of the layer denominators. When wD is at most 2^63−1, scale each signed row weight to denominator D, accumulate exactly in int64, and select by exact anchor pruning. Otherwise retain the dyadic certificate and integer boundary fallback. The threshold follows from the largest possible magnitude of an intermediate sum or its negation for sorting; no measured run time enters the decision.

Use all 47 historical panels, the original 10% budget, no test outcomes and the same training-to-support timing scope. Compare five paths. (1) Exact native when safe and dyadic otherwise. (2) Native when safe and arbitrary-precision anchor pruning otherwise. (3) Native exhaustive when safe and arbitrary-precision exhaustive otherwise. (4) Always dyadic. (5) Floating-point pruning. Randomize the order of distinct calls within each of five rounds, after one warm-up. Where paths execute identical code, time it once and reuse the observation in both policies. This enforces a ratio of exactly one for an identical path. Independently check identical ballots across calls and exact membership against exhaustive integer scores. Report observed-data panels separately for the native-safe and wider strata, panel-weighted and equal-source medians, including comparisons to float. These are machine-specific descriptive timings.
