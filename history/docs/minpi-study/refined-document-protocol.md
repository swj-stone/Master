# 训练内投票估计与自选宽度的进一步验证

本轮改动针对 minPI 的投票估计和自适应列数。主要结果沿用每组真删列、平衡准确率较全特征最多低 0.02、从已有词袋到预测的总耗时更短。与筛选基线比较时，再要求列数不多于该基线、分数较它最多低 0.02、总耗时也更短。额外报告允许多 10% 列、至少快 10% 的结果。

开发仅使用已有 UCI 语料中 SMS、Amazon、IMDb、Yelp 的第一折，共四个外层配置。在候选代码和参数冻结后，使用其余 13 个 UCI 划分与 SpamAssassin 的三个选择种子验证。邮件三个种子共用一个发布批次测试集。这些来源在之前的研究中已有结果，本轮记录为开发留出检验，且保持与四个开发配置的计数可分辨。候选的每次拟合只接触该外层划分的训练数据。

在四个开发配置上检查了全训练行的跨折投票、解析留一投票、匹配标准化的岭惩罚以及联合模型贡献。开发结果未显示这些方案能一致保住旧版表现，保留对应实现与负面结果。正式候选固定为三次训练子样本投票的中位数聚合。每次最多抽 512 个训练样本，复用旧算法的零同伴和一个强同伴情境；每个情境的端点先分别在三次抽样中取中位数，再对两个情境取较小值。三个是能形成中位数的最小奇数重复量，用于降低一次不利子样本主导排名的影响。第一子样本使用原选择种子，另外两个从固定 SeedSequence 生成。自动宽度仍按 99% 正票量、词表平方根下界、半宽上界决定。选择依据限定于四个开发配置，IMDb 第一折较旧 minPI 的 0.742917 下降约 0.0211，属于与旧版比较的精度失败；该折全特征约为 0.713052，候选分数高于全特征。这两个比较分别保留。

正式代码入口固定为 robust_document_minpi.robust_document_top_from_training 的默认三次中位数规则。原生融合实现须先与 repeated_document_minpi 的参考实现逐项检查端点、最终分数和所选支持，再进入正式计时。冻结后同时测原 20 个配置，汇总中保留开发四例、UCI 留出十三例、邮件三种子的来源标记。新增土耳其语数据只在冻结后评价。

同场对照包括上一版快速 document minPI、全特征、固定半宽 F 检验、卡方检验、全训练单词边际岭及均匀随机。对每个新候选分别加入与其实际列数相同的 F、边际岭、随机。基线免费得到各候选所选宽度。所有方法保留同一训练词表和同一单线程标准化岭分类器，训练词表中每列均实际变化。旧 minPI、全特征和所有固定半宽对照的所选列和逐条预测都核对上一轮归档。

每个配置先预热所有方法，再按照种子确定的顺序轮换计时，重复次数等于方法数量，每个方法在各位置各出现一次。每次重新拟合筛选器并计入完整选列、切片、标准化、分类器训练和预测。计时之外保存评分、列索引、逐样本预测和投票向量。第二个独立进程改变初始轮换顺序，采用相同代码和输入；稳定成功要求相同配置两轮均通过。另启进程逐项复现输出。

各候选在每个实际宽度额外抽 20 个均匀随机支持。随机质量评估在正式计时之外单独运行，保存支持与预测的摘要和准确率。重新运行时逐项比对已保存的抽样结果。总表分别列出开发四例、留出 UCI 十三例与邮件三个种子的结果。按来源检查 minPI 的精度、列数和计时变化，保留失败配置。

本轮另在算法冻结后检验原作者发布的土耳其语 SMS 语料。输入文件 SHA-256 为 fe4e9b1e7f4d2a6281a89f864b730e1fc7cd894ed29a816ecbf037b048c7025d，Message 为短信正文，Group 为 1 表示垃圾短信、2 表示正常短信。使用与先前 UCI 试验相同的无标签词袋重复排除、训练内词表和变化词项处理，按 StratifiedKFold 的三个分层划分，固定 shuffle 种子 39191；三折的选列种子依次为 1129、2027、3469。测试文档投影到训练词表后再排除训练中已经出现的完全相同词袋。该来源以 external 阶段单独运行，基线在相同输入上现场计时和保存，所有配置和失败均报告。既有 17 个 UCI 划分及邮件的开发留出检验与该新增来源分别统计。[原作者发布的语料](https://github.com/onrkrsy/TurkishSMS-Collection)
