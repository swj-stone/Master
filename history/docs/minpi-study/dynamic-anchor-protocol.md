# Dynamic update of an exact anchor cutoff

Start with a fixed ballot matrix, peer counts and budget. Each call validates the ballots, builds row pivot weights on the common denominator, computes the exact largest-peer-count anchor for all columns and sorts by descending anchor score, breaking ties by ascending index. Use signed int64 when the symmetric partial-sum bound fits and Python integers elsewhere. The three methods share these steps and the same column scoring kernel. All fill the initial budget in one batch and evaluate the secondary layers of those columns. Stop when the next unread upper key is below the weakest accepted key. No sorted list, complete scores or layer weights are passed from one call to the next.

The batch control freezes the initial cutoff and scores all qualifying outsiders together. The streaming control freezes the same key and scores those outsiders one at a time. The dynamic policy also scores one outsider at a time and updates the cutoff to the weakest of its current top h after each completed score. The streaming methods use the same heap and evaluation order. All three credit the tie rule when pruning. Their completed-column counts include the initial h and any scored outsiders. A full-budget input can return all indices immediately. Stopping is sound because each unseen score-index key is bounded above by its anchor-index key, and unseen anchor keys are ordered.
