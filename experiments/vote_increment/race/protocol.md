# Block-omission voting pilot

The six existing prepared datasets and seed 42 are development data. Preserve the native XGBoost Gain order throughout. For prefix width k, its omitted suffix casts a signed comparison between the additive native margin with and without the entire suffix. Draw eight random coalitions of each fixed size nearest to 1/8, 1/2 and 7/8 of the retained prefix. Use class-balanced pair concordance on raw one-vs-rest margins for classification and normalized squared error for regression. Compute votes on the vote rows only. These votes describe an additive fixed-model surrogate and provide no guarantee about future refits.

The minimum and arithmetic mean aggregate identical observations. Native Gain uses cumulative total gain along the same documented ranking, scaled by its full-model gain over a null predictor on the vote partition. Each candidate first tries the smallest width whose suffix vote loss and all later losses are at most .005. An accepted proposal permits a check at .02. A rejection permits a rescue at .00125. A true native fit must score within .005 of full validation performance on the width partition. All three strategies allow up to four native fits including training the full model and the final deployment fit. Reuse repeated widths and train no proxy models. Count and time scoring, ranking, native fits and prediction. Compare the three arms in the prespecified six datasets using the existing gate.

The mechanism under test is whether a weak marginal contribution under one availability context identifies a better native width at a fixed budget. The minimum does not create a valid early-stopping certificate for native XGBoost refits. A successful pilot additionally needs an aggressiveness-matched direct control and held-source confirmation.
