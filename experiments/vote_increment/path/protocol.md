# Gain-path vote calibration, development round

All three arms traverse the same native Gain order. Each XGBoost split casts its training gain as a vote conditional on all distinct features on its root-to-node path being present. At fixed coalition size s, a path requiring d features casts a vote with probability C(s,d)/C(p,d). Aggregate the fraction of expected vote mass lost by deleting a suffix at the nearest integer sizes to one quarter, one half and three quarters of p. Minimum and arithmetic mean consume the same three fractions. Direct Gain uses the fraction of native total gain lost by the same deletion, supplied without path construction. The profiles are surrogates for width nomination.

After measuring the full model and one-column model, interpolate by validation utility along the profile between the smallest measured acceptable width and its nearest narrower rejected width. Measure up to three interior widths, accept the smallest measured model within 0.005 of full validation utility, and refit on development rows. All arms can terminate on a unit-width bracket, share cached duplicate supports within an arm, use the same native model and measure complete standalone time. Maximum six fits including final refit. Score the six original development tasks, first seed 42. Timing is exploratory until replicated. Use the paired audit without transferring wins from another design.
