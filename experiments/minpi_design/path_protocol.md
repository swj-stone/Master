# Native-margin voting development revision

Following the weak raw-linear proposals on the original prepared tasks, use the existing full native XGBoost model as teacher. Its inexpensive path contributions sum to each raw margin. They require all raw inputs during selection and cannot be deployed with missing raw columns. Retrain XGBoost from raw retained columns for every native check and for final prediction. Use only the original six development tasks at seed 42.

Use at most 512 fitting records to estimate the game over centered teacher contribution columns, sharing one scalar per raw feature across output classes. Center multiclass margins across classes per example. Scale each feature by its penalized root second moment and use its empirical scalar Gram; the response is the centered intact teacher margin. Compare compensated minimax deletion, compensated pooled deletion, mean absolute path contribution and ordinary Gain. Use identical fit, validation, test and base model settings from the native CPU experiment.

Check a common dyadic width grid in two ways. A direct ascending scan returns its smallest passing width. Ordinary bisection treats the full width as an observed pass and zero as outside the candidate set. It checks the midpoint, retains the pass/fail bracket and stops at adjacent widths. Nonmonotonic validation scores may cause bisection to skip a passing width. All four rankers use both schedules. Neither schedule receives a width oracle. Record every actual native check with timing charged to every method that uses it and stage all final predictions before scoring. Record simultaneous CPU activity when reporting small runtime differences.
